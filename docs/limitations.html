Current limitations

WP-A01–WP-A18 establish a locally tested Linux development candidate. They do not authorize a public production-readiness claim.

LocalPassed

Normal, race, vet, build and recovery gates.

ScaleBounded

500-post query proof, not full browser dogfood.

ExternalRequired

Security and assistive-technology review.

ReleaseNot yet

No production support claim or public tag.

  • Watchpost Agent supports Linux amd64/arm64; macOS and Windows monitoring are not supported.
  • HTTP, TCP, TLS, DNS and ICMP are durably scheduled. SNMP profiles are durable, but recurring device polling is not: polling passwords are deliberately transient.
  • SNMP is read-only. Cameras, arbitrary consumer IoT, PLC writes, and building-control commands remain future research.
  • The built-in investigation provider does not infer causality; production model-provider configuration and evaluation remain unfinished.
  • Fleet federation lacks sustained two-node partition and reconciliation evidence.
  • Backups require a cleanly stopped node; online encrypted scheduled backup is not implemented.
  • The 500-post test proves a server query bound, not production browser hierarchy. No multi-day soak, external security assessment, screen-reader audit, or assistive-technology audit has been completed.
Authority boundary

Watchpost is not a safety system, SCADA/HMI, or autonomous remediation engine. Missing evidence is never healthy evidence, and model output is never authorization.
