Docs · Architecture

Posts, agents, and monitoring methods

Watchpost keeps the thing you care about—the post—at the centre. A separately installed Watchpost Agent is one way to observe a machine; central checks and device adapters cover posts that should not run software.

Install first, pair second

The agent is useful software before it has authority to send data. Installation creates its service, private state, bounded queue, local website, and CLI. Pairing is a later, revocable relationship with one Watchpost post.

Website and CLI are peers

Local website

The pleasant default for installation status, pairing, collector selection, delivery health and diagnostics.

Command line

The complete server-friendly surface for SSH, headless systems, automation, configuration management and recovery.

Both surfaces call one application service and persist one state model. A feature is not complete if it works through only one surface without an explicit reason.

The first working profile

On Linux, an approved agent immediately reports CPU, memory, root-filesystem utilisation and uptime, then repeats once per minute. Watchpost stores those signals against the selected post, so the existing survey, graphs and rules work without creating a second “collector post.”

./watchpost-agent install
./watchpost-agent pair --server https://watchpost.example.net
./watchpost-agent pair-status

The local website performs the same steps. The command line exists for headless servers; it is not a lesser or separate configuration path.

Connection inventory

Once approved, the post row shows the agent hostname, platform and explicit connection health. These are monitoring details beneath the post—not another inventory object. A host with no agent says so directly and keeps its compact Connect action.

Configurable local evidence

The agent website and watchpost-agent configure command edit the same collector profile. Operators can enable CPU, memory, one-minute load and uptime, choose up to eight absolute filesystem paths, and set a bounded 15–3600-second interval. Filesystem observations retain their path label.

Safe local boundary

The agent website listens on loopback by default and protects state changes with an authenticated local session, Origin validation and CSRF controls. Non-loopback access is an explicit advanced mode. Agent delivery is outbound, so monitored machines do not require an inbound management port.

Lifecycle matters

Archiving a post, revoking an agent, resetting local credentials and uninstalling the agent are different operations. Deleting a post revokes its server authority but cannot silently remove software from another machine.
