Getting started

Watchpost is not installable yet. The project has published its product boundary and ordered engineering programme before implementing the server.

What you can inspect today

The application repository contains a living engineering handover and development plan. They define the intended terminology, security invariants, architecture, milestones, and evidence required at each checkpoint.

git clone https://github.com/watchpost-ops/watchpost.git
cd watchpost
less HANDOVER.md
less PLAN.md

The intended first deployment

The first usable Watchpost is planned as a single self-hosted service: a Go binary containing the Nift-built web interface, backed by a migrated SQLite database. One node should monitor its own environment without an external coordinator.

The eventual shape is deliberately conventional:

watchpost serve
# browser → authenticated Watchpost UI
# server  → collectors + rules + incidents + SQLite
Proposed interface

The command above communicates the deployment goal; it is not yet a supported CLI contract.

What comes first

  1. Threat model, domain contracts, and state machines.
  2. Authenticated single-node service and durable database.
  3. Inventory, collectors, signals, checks, and bounded retention.
  4. Rules, alerts, notifications, and incident workflow.
  5. Evidence-grounded agent investigation.
  6. Typed actions, approvals, and optional federation.

See the public roadmap for the full programme.
