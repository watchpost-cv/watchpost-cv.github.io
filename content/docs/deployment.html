Deployment

Watchpost is designed for a simple self-hosted first deployment and a distributed future. This page describes the target architecture; concrete installation commands will follow the first runnable release.

Single node

The proposed package is one Go executable with the Nift-built frontend embedded. A private data directory holds SQLite state, secrets, retained telemetry, diagnostic material, and agent session data. Static assets need no sidecar directory in a normal release.

Network boundary

Local development may bind to loopback. Remote use should put Watchpost behind HTTPS through a trusted reverse proxy or use native TLS when implemented. Forwarded client and scheme headers must only be trusted from explicitly configured proxy peers.

Backup boundary

A useful backup includes the database, configuration, encrypted secret material, and any external telemetry segments referenced by durable state. Backup and restore instructions will name the exact consistency procedure once storage exists.

Node independence

A node should continue collection, rules, alerts, and incidents when disconnected from peers. Federation will use explicit enrollment, node identity, rotation, revocation, bounded store-and-forward queues, protocol compatibility, and reconciliation.

Release targets

The initial release programme targets Linux, macOS, and Windows on amd64 and arm64. Support remains provisional until each build passes the platform’s behavioural gates—not only compilation.

Not available yet

Do not expose an unfinished development server to the internet. Authentication, proxy trust, upgrades, recovery, and security tests are part of the single-node foundation milestone.
