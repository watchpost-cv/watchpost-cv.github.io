Roadmap

Build the evidence chain in order.

The agent is not checkpoint one. Watchpost first needs reliable collection, durable state, deterministic rules, and coherent incidents—the substrate an operational agent must trust.

WP00–WP03 · Trustworthy foundation — implemented

Contracts, threat model, Go service, embedded UI, SQLite recovery, authentication, capabilities, audit, and proxy boundaries.

WP04–WP05 · Posts and ingestion — implemented

Typed post inventory, topology, collector protocol, authenticated push/pull, provenance, quality, bounds, replay defence, and backpressure.

WP06–WP08 · Useful monitoring — implemented

Linux host collection, HTTP/TCP/DNS/TLS checks, durable history, freshness, retention, charts, comparisons, and export.

WP09–WP10 · Alerts and notification — implemented

Replayable deterministic rules, alert lifecycle, noise control, routing, email, webhooks, retries, and delivery audit.

WP11–WP12 · Incidents and evidence — implemented

Durable incidents, linked alerts, notes, status transitions, bounded redacted logs, and explicit deployment and configuration changes are implemented.

WP13 · Devices beyond hosts — implemented

Read-only SNMPv3 monitoring for network devices first, then UPS/PDU and environmental-sensor posts with versioned vendor profiles.

WP14–WP15 · Agent and actions — implemented

Evidence-citing read-only investigation first; typed, scoped, approved, audited low-authority actions only after that boundary is proven.

WP16 · Fleet contracts — implemented

Independent nodes, selective federation, identity, revocation, bounded store-and-forward, partitions, and explicit reconciliation.

WP17–WP18 · Development release candidate — local gate complete

Portable artifacts, installers, upgrades, HTTPS deployment, long-run campaigns, fuzzing, disaster recovery, security review, and dogfooding.
