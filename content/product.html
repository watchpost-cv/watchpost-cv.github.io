Product direction

A watchpost for every environment.

Each node is intended to remain useful by itself: collect locally, retain history, evaluate rules, open incidents, and investigate. Connect nodes into a fleet when coordination adds value—not because the product requires a cloud control plane.

One operational model

Monitoring that remembers the investigation.

Watchpost connects inventory, telemetry, alert state, incidents, human notes, agent conversations, and approved actions without flattening them into an undifferentiated event stream.

Targets

Durable inventory

Hosts, services, endpoints, applications, ownership, dependencies, labels, and maintenance state form the operating map.

Telemetry

Signals and events

Measurements and transitions retain time, source, quality, freshness, and units so operators can distinguish failure from uncertainty.

Response

Alerts and incidents

Rules create visible state; incidents gather related evidence and preserve the complete path through acknowledgement and resolution.

Understanding

Operational agent

Investigation tools traverse bounded data and expose evidence. Privileged actions are typed, scoped, approved, and audited separately.

Designed to grow

Local first. Fleet capable.

A disconnected Watchpost should continue monitoring its environment. Federation will add selective sharing, fleet-wide views, and coordination while preserving local authority and bounded failure.

Independent nodes

Collection, rules, incidents, dashboards, and investigation work on one node without a mandatory external service.

Selective federation

Nodes share only configured inventory, events, and incident state across explicit trust and tenancy boundaries.

Store and forward

Bounded queues, identity, ordering, deduplication, revocation, and reconciliation make disconnection a designed state.

Open interfaces

Versioned collector and integration contracts allow Watchpost to meet heterogeneous environments without an unsafe in-process free-for-all.
